# Проект «Библиотека» на Python + PyQt6

## О проекте

Учебный проект студента: настольное приложение для учёта библиотеки. Предыдущая версия была сделана в Microsoft Access, преподаватель её принял, но назвал «адом для пользователя». Главная цель новой версии — **простота и удобство для библиотекаря**: минимум кликов, понятный интерфейс без технических деталей.

Работа сдаётся по частям: на каждом занятии студент показывает преподавателю новую часть. Поэтому код пишется **постепенно, по одной части за раз**.

## Стек

- Python 3.10+
- PyQt6 — интерфейс
- sqlite3 из стандартной библиотеки — база данных (файл `library.db` рядом со скриптами)
- Без ORM и без других сторонних библиотек. Если без новой библиотеки не обойтись, сначала спроси.

## Правила работы

1. **Одна часть за раз.** Пиши только ту часть, о которой просят, объёмом примерно 250–350 строк. Не забегай вперёд и не дописывай следующие части «заодно».
2. **Каждая часть запускается.** После каждой части `python main.py` (или `python database.py` для первой части) работает без ошибок, а новое видно и можно показать.
3. **Не ломай готовое.** Уже написанные функции и их параметры не меняй без необходимости. Если менять пришлось, перечисли в ответе, что и почему изменено.
4. **В конце каждой части** напиши коротко:
   - какие файлы созданы или изменены;
   - что показать преподавателю (3–5 пунктов);
   - как проверить, что всё работает.
5. **Перед коммитом проверь код**: запусти его, а если есть окна — хотя бы импорт модулей и создание окон без ошибок.

## Стиль комментариев (обязательно)

- Комментарий почти у каждой строки кода, в конце строки через `#`.
- На русском, простым языком студента, коротко.
- **С маленькой буквы и без точки в конце.**
- В SQL-запросах комментарии через `--` тем же стилем.
- В начале каждого файла 2–3 строки комментария: какая это часть и что в файле.

Пример:

```python
self.search.textChanged.connect(self.refresh)  # при каждой букве обновляем таблицу
```

Текст, который видит пользователь (кнопки, сообщения, заголовки), — на русском, с заглавной буквы и нормальной пунктуацией.

## Что уже сделано

**Часть 1 — `database.py`** (готово, не переписывать). Таблицы: `genres`, `authors`, `books`, `book_authors`, `readers`, `staff`, `copies`, `operations`. Экземпляр считается в наличии, если `copies.reader_id IS NULL`; отдельного поля «в наличии» нет. Пароли хранятся хешем sha256.

Готовые функции: `init_db`, `connect`, `check_login`, `get_genres`, `get_readers`, `add_reader`, `search_books(text, only_available)`, `issue_book`, `return_book`, `get_issued`, `get_debtors`, `get_history`, `get_stats`.

Тестовые учётные записи: `admin` / `1234` (администратор), `lib` / `1111` (библиотекарь).

Новые функции работы с базой добавляй в `database.py` в том же стиле: `with connect() as conn`, параметры только через `?`.

## Требования задания преподавателя (должно быть к концу)

Хранимые данные:
- книги: название, автор, жанр; у книги есть экземпляры с инвентарным номером;
- книги и авторы связаны «многие ко многим»;
- читатели: ФИО, телефон, фактический адрес, дата рождения; номер читателя = номер читательского билета;
- сотрудники.

Функции:
- выдача и возврат книг с датами выдачи и возврата;
- каждая операция фиксирует: кто, что, когда, какая операция;
- поиск двух видов: среди всех книг и среди доступных сейчас;
- сортировка книг, разделение по жанрам;
- отчёты: какие книги выданы, какие в наличии, когда вернут, должники;
- роли: администратор — первоначальное наполнение и удаление записей; второй сотрудник (библиотекарь) — регистрация читателей, выдача и возврат;
- главное окно с четырьмя разделами: Администрирование, Выдача, Отчёты, Отдача (возврат).

## Требования к удобству (главное отличие от версии в Access)

- **Одно главное окно** с боковой панелью или вкладками вместо множества всплывающих окон. Разделы: Выдача, Возврат, Каталог, Читатели, Отчёты, Администрирование (последний виден только администратору).
- **Поиск по мере ввода** везде, без окон ввода параметров. Регистр букв не важен.
- **Выдача в одном экране:** найти читателя по ФИО или номеру билета → найти книгу → кнопка «Выдать». Срок возврата подставляется сам (+14 дней), но его можно изменить. Сотрудник берётся из входа, выбирать его не нужно.
- **Возврат в один шаг:** ввести инвентарный номер или выбрать из списка выданных → «Принять». Просрочка видна сразу.
- **Пользователь не видит внутренних кодов**, кроме инвентарного номера и номера билета: везде названия и ФИО.
- **Таблицы** сортируются щелчком по заголовку, строки выбираются целиком, двойной щелчок открывает карточку для изменения.
- **Цвет:** просроченные выдачи выделены красным, книги в наличии — зелёным текстом статуса.
- **Удаление** — только у администратора и только с подтверждением; запрещено, если есть выданные экземпляры.
- **Понятные сообщения об ошибках** вместо технических текстов; пустые обязательные поля подсвечиваются.
- **Клавиатура:** Enter нажимает основную кнопку, Esc закрывает диалог, Tab переходит по полям в логичном порядке.
- **Строка состояния** внизу: кто вошёл и с какой ролью, кнопка «Выйти» для смены пользователя.
- **Главный экран** показывает сводку: книг, экземпляров, выдано, должников.
- Отчёты можно сохранить в файл (CSV) и распечатать (средствами PyQt6).
- Аккуратное единое оформление: читаемый шрифт, одинаковые отступы и кнопки, окно нормального размера при запуске.

## Примерный план частей

1. `database.py` — база, тестовые данные, функции. **Готово.**
2. `main.py` + окно входа + каркас главного окна с разделами и сводкой.
3. Каталог: таблица экземпляров, поиск по мере ввода, фильтр «только доступные», фильтр и сортировка по жанру.
4. Выдача и возврат.
5. Читатели: список, поиск, регистрация, карточка читателя с его книгами.
6. Карточка книги для администратора: добавить, изменить, удалить; авторы и количество экземпляров.
7. Отчёты: выданные, в наличии, должники, история операций; сохранение в CSV и печать.
8. Администрирование: жанры, авторы, сотрудники; разграничение прав по ролям.
9. Оформление, README, финальная проверка по всем требованиям.

Порядок можно уточнять с пользователем, но каждая часть должна давать видимый результат.
