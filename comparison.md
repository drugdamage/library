# Access и Python: сравнение БД «Библиотека»

## Что сравниваем

Одну задачу учёта библиотеки в двух реализациях: Microsoft Access (таблицы, запросы, формы, макросы/VBA) и Python + PyQt6 + SQLite (SQL, функции, обработчики событий). Интерфейс и пользовательские действия должны быть сопоставимы, чтобы сравнивать способ реализации.

Источники по прежней работе: три документа в `docs/` и исходный файл `Библиотека.accdb`. 18.11.2026 прочитаны таблицы и имена объектов Access без запуска форм и макросов. Ниже отделены результаты этого чтения, сведения методички и проверки, требующие запуска Access. Результаты Python проверяются локальными тестами. Временные замеры обеих версий пока не проводились.

## Что проверено в исходной Access-базе

В таблице Access означает добавленный файл, Python — начальный тестовый набор.

Файл прочитан через `access-parser 0.0.6` в отдельном временном окружении. Это инструмент разовой проверки, в зависимости приложения он не добавляется. SHA-256 файла до и после чтения совпал: `455f13f5b77215bfc21a5b2d3fe41d0e5b72a16b286e6180f70926f9d9d0f47d`.

Одинаковое количество читателей не доказывает совпадение их записей. Сравнивать итоговые числа и скорость на этих разных наборах некорректно; сначала нужны одинаковые исходные данные на копиях баз. Перенос данных в этой итерации не выполнялся.

## Сопоставление задач

### Создать таблицы и простую форму

| Среда                   | Реализация                                             |
| ----------------------- | ------------------------------------------------------ |
| Access                  | Конструктор таблиц, связи, мастер форм, привязка полей |
| Python / PyQt6 / SQLite | SQL-схема и код виджетов, заполнение таблицы вручную   |

**Вывод и статус:** Для типовой формы Access требует меньше ручного кода; это оценка подхода, время не измерено

### Сделать печатный отчёт

| Среда                   | Реализация                                     |
| ----------------------- | ---------------------------------------------- |
| Access                  | Встроенные мастер и конструктор отчётов        |
| Python / PyQt6 / SQLite | Нужно отдельно реализовать подготовку и печать |

**Вывод и статус:** Здесь Access удобнее; в Python сейчас есть таблица и CSV, печати ещё нет

### Поиск при вводе

| Среда                   | Реализация                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------ |
| Access                  | В «Доработки 2» уже есть `On Change`, `TempVars`, `Requery`, фильтр наличия          |
| Python / PyQt6 / SQLite | `textChanged`, `search_books`, пользовательская SQL-функция `py_lower` для кириллицы |

**Вывод и статус:** Реализуемо в обеих системах; живой поиск не преимущество Python

### Обновление сводки

| Среда                   | Реализация                                          |
| ----------------------- | --------------------------------------------------- |
| Access                  | В «Доработки 2»: `On Activate`, `DCount`, `Requery` |
| Python / PyQt6 / SQLite | `HomePage.refresh`, `get_stats` при возврате в меню |

**Вывод и статус:** Одинаковый результат разными средствами

### Изменение срока выдачи

| Среда                   | Реализация                                                      |
| ----------------------- | --------------------------------------------------------------- |
| Access                  | Проверить выражение даты и действия формы выдачи в готовой базе |
| Python / PyQt6 / SQLite | `LOAN_DAYS`, параметр `days`, выбор срока в форме               |

**Вывод и статус:** Python позволяет проверить правило без открытия формы; изменение Access ещё не выполнено

### Атомарность выдачи и журнала

| Среда                   | Реализация                                                                                   |
| ----------------------- | -------------------------------------------------------------------------------------------- |
| Access                  | Доступны DAO `BeginTrans`, `CommitTrans`, `Rollback`; наличие их в готовой базе не проверено |
| Python / PyQt6 / SQLite | `BEGIN IMMEDIATE`, обновление и журнал в одном `with connect()`                              |

**Вывод и статус:** Транзакции есть в обоих подходах. В Python откат при сбое журнала подтверждён автотестом

### Повторная выдача и возврат

| Среда                   | Реализация                                            |
| ----------------------- | ----------------------------------------------------- |
| Access                  | Проверить ограничения макросов/кода на копии `.accdb` |
| Python / PyQt6 / SQLite | Проверки состояния в `issue_book`, `return_book`      |

**Вывод и статус:** Python-сценарии проверены; результаты Access ожидают проверки

### Книга с несколькими авторами и экземплярами

| Среда                   | Реализация                                                       |
| ----------------------- | ---------------------------------------------------------------- |
| Access                  | В методичке отдельные связанные формы книг, связей и экземпляров |
| Python / PyQt6 / SQLite | Одна функция `add_book` и форма; все записи в одной транзакции   |

**Вывод и статус:** Демонстрация гибкости композиции действий в Python, но аналог возможен в VBA

### Регистрация читателя

| Среда                   | Реализация                                                        |
| ----------------------- | ----------------------------------------------------------------- |
| Access                  | Связанная форма, обязательные поля и правила проверки             |
| Python / PyQt6 / SQLite | Виджеты формы + проверка обязательных полей и даты в `add_reader` |

**Вывод и статус:** Access проще для типового ввода; Python удобно проверять повторно без GUI

| Среда                   | Реализация                                                                                               |

## Где именно видна гибкость Python

`database.py` не зависит от Qt: выдачу, возврат, регистрацию и пополнение фонда вызывают формы и тесты. Изменение правила можно проверить на временной базе без кликов. В `reports.py` четыре отчёта описаны единообразно: источник данных и список полей. Один экспорт используется всеми отчётами. В `ui/workflows.py` таблицы, сортировка и сообщения переиспользуются разными формами.

Показательный эксперимент — авария записи журнала: тест создаёт временный триггер, который отклоняет вставку. После неудачной выдачи экземпляр остаётся свободным, после неудачного возврата — выданным. Код проверки хранится в Git и повторяется после каждого изменения. Это преимущество выбранной структуры проекта и удобства инструментов Python; аналогичную надёжность можно реализовать и в Access с VBA/DAO.

Карточка читателя добавлена 18.11.2026: одна функция `get_reader_card(reader_id)` читает связанные данные в общей транзакции чтения, а интерфейс выводит их в двух вкладках. Проверки подтверждают, что возврат убирает книгу из текущих, сохраняет историю прежнего читателя и не смешивает её с историей следующего заёмщика того же экземпляра. Старые сроки в журнале не подсвечиваются как текущая просрочка. Так можно показать расширение приложения и проверку связанных данных без изменения таблиц и главного меню.

## Что показать преподавателю за 5–10 минут

1. Войти как `lib / 1111`. Показать четыре кнопки, недоступное администрирование и исходную сводку.
2. «Отчёты» → «Поиск книг»: ввести `СТРУ`, включить «Только доступные», выбрать жанр; сравнить с формой поиска Access.
3. «Выдача»: найти читателя, выбрать свободный экземпляр и срок 21 день. Запомнить инвентарный номер. Выдать и проверить сводку/отчёт.
4. Снять фильтр наличия, найти этот экземпляр, повторить выдачу: получить отказ. В «Отдача» принять его; проверить две записи журнала.
5. «Выдача» → «Читатели»: открыть карточку Орлова двойным щелчком. На начальном наборе — одна книга на руках и три записи истории, включая возврат. Принять экземпляр №9 в «Отдача», снова открыть карточку: текущих книг нет, история выросла до четырёх записей. Затем зарегистрировать читателя и показать его пустую карточку.
6. Войти как `admin / 1234`, добавить книгу с двумя авторами и тремя экземплярами. Найти их в поиске. Создать резервную копию в отдельный файл.
7. Открыть должников и полный журнал, сохранить CSV. Продемонстрировать те же данные в Access, если файл доступен.
8. Выполнить `python -m unittest discover -s tests -v`. Объяснить тест отката журнала и связь тестов с изменением правил.

Демонстрация изменяет базу. Для повторяемого показа использовать отдельную копию проекта/БД; не удалять рабочую `library.db`. Автотесты сами создают временные базы.

## Протокол сравнительной проверки

Заполняется после запуска обеих программ на одинаковых исходных данных. Для времени разработки фиксировать начальное состояние и точное изменение; для скорости — одинаковую задачу и объём данных. Автотест не заменяет замер действий оператора. Время Access / Python для всех экспериментов ниже пока не измерено.

| Эксперимент                                               | Python                                                                           | Access                                                    |
| --------------------------------------------------------- | -------------------------------------------------------------------------------- | --------------------------------------------------------- |
| Поиск `СТРУ`, доступные                                   | 2 экземпляра на исходных тестовых данных                                         | По методичке также 2; запуск не выполнен                  |
| Выдача → повторная выдача → возврат                       | Успех → отказ → успех, две новые записи журнала                                  | Не проверено на `.accdb`                                  |
| Сбой журнала                                              | Частичные изменения откатываются                                                 | Не проверено на `.accdb`                                  |
| Добавить книгу с несколькими авторами                     | Одна транзакция, проверяется тестом                                              | Не проверено на `.accdb`                                  |
| Изменить срок 14 → 21                                     | Параметр формы передаётся функции, дата проверяется тестом                       | Не проверено на `.accdb`                                  |
| CSV одного отчёта                                         | Проверяется содержимое, заголовки и кодировка                                    | Не проверено на `.accdb`                                  |
| Карточка после возврата и новой выдачи того же экземпляра | Текущие книги и личная история разделены; изоляция по читателю проверена тестами | Найдена `фЧитатели`; аналогичный сценарий ещё не проверен |
| Совпадение оформления                                     | Восстановлены четыре кнопки и порядок переходов                                  | Нужны снимки готовых форм                                 |

## Ограничения и предварительный вывод

Access удобен для быстрого создания типовых связанных форм и печатных отчётов. Python требует больше кода и ручной сборки интерфейса, зато в этом проекте логика отделена от окон, повторно используется и автоматически проверяется. Это основной тезис работы. Вывод о скорости, полной функциональной эквивалентности или точном совпадении внешнего вида пока не обоснован.

Учебные роли не защищают файл БД от прямого изменения, SHA-256 без соли не подходит для эксплуатационного хранения паролей. Многопользовательская нагрузка, миграция данных из Access и готовый установщик не исследовались.
