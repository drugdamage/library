conn = sqlite3.connect("library.db")      открыть базу, если файла нет он создастся
conn.row_factory = sqlite3.Row            чтобы писать row["title"] вместо row[1]
conn.execute("PRAGMA foreign_keys = ON")  включить проверку внешних ключей, по умолчанию выключена

with connect() as conn:                   в конце блока изменения сохранятся сами (commit),
    ...                                   а если была ошибка, всё откатится (rollback)

параметры в запрос передаю только через ?, а не через f-строку, так нет sql инъекций:
conn.execute("SELECT * FROM readers WHERE id = ?", (5,))
запятая в (5,) обязательна, иначе это не кортеж

conn.execute(...).fetchone()        одна строка или None
conn.execute(...).fetchall()        список всех строк
cur.lastrowid                       id только что добавленной строки
conn.executemany(sql, список)       один запрос для многих строк
conn.executescript(текст)           выполнить несколько запросов подряд, так создаю таблицы

conn.create_function("py_lower", 1, py_lower)
так можно дать sqlite свою функцию на python. понадобилось потому что LOWER() и LIKE в sqlite
не понимают регистр русских букв, а поиск должен работать без учёта регистра

обновление 06.11.2026 — сравнение Access и Python

Главная цель теперь сравнить способы реализации одной задачи. Access — целая среда,
поэтому сравниваем его с Python + PyQt6 + SQLite. Живой поиск и сводка в Access уже
есть по документу «Доработки 2», это не новые преимущества Python.
ТЗ переписано в ТЗ.md, сравнение реализаций находится в comparison.md.

что добавлено:
ui/workflows.py — общая таблица Table и формы CatalogPage (поиск/выдача),
ReturnPage, ReadersPage, ReportsPage, AdminPage. Страницы создаются при первом
открытии, при повторном открытии заново читают данные из БД.
ui/main_window.py — четыре кнопки по образцу Access, кнопка возврата в меню,
обновление сводки. Старую боковую панель убрали ради сопоставимости.
reports.py — описание четырёх отчётов (функция + поля) и общий CSV-экспорт.
CSV пишется через csv.writer, кодировка utf-8-sig, разделитель ;.
Экспортируется текущий порядок строк после сортировки. Текст с =,+,-,@
экранируется апострофом, чтобы табличный редактор не выполнял формулы.

database.py:
LibraryConnection закрывает соединение после commit/rollback в with.
Важно: обычный sqlite3.Connection в with завершает транзакцию, но не закрывается.
BEGIN IMMEDIATE в выдаче/возврате получает блокировку записи до проверки состояния.
Проверка, изменение экземпляра и запись журнала — одна транзакция.
add_reader проверяет обязательные поля и дату рождения независимо от интерфейса.
get_authors() — список авторов для выбора.
add_book(title, genre_id, author_ids, year, copies, staff_id) — книга, связи с
авторами и экземпляры одной транзакцией; роль администратора проверяется в БД-функции.
backup_database(path, staff_id) — sqlite3.Connection.backup, не копирование
открытого файла через shutil; исходную и существующую целевую БД не перезаписывает.
Все изменения схемы отсутствуют: старая library.db подходит без пересоздания.

новые стандартные модули: csv (экспорт), tempfile и unittest (изолированные тесты).
Зависимости остались прежними, только PyQt6. Новые библиотеки не устанавливались.
Новые Qt-классы: QTableWidget/QTableWidgetItem, QHeaderView, QComboBox,
QCheckBox, QSpinBox, QDateEdit, QFileDialog, QMessageBox.
UserRole хранит id экземпляра в каждой ячейке: сортировка не ломает выбор записи.
DisplayRole хранит числовые значения как числа: 10 сортируется после 2.

проверка:
python -m unittest discover -s tests -v
QT_QPA_PLATFORM=offscreen python -m unittest discover -s tests -p 'test_ui.py' -v
Тесты перенаправляют DB_PATH на временный файл. Рабочая library.db не меняется.
Триггер RAISE(ABORT) искусственно ломает журнал, чтобы проверить откат операции.
Это пример того, как Python позволяет проверять логику независимо от окон.
В Access транзакции тоже есть (DAO), но их наличие в сданной базе надо проверить.

обновление 18.11.2026 — карточка читателя и исходный Access

Открытие карточки читателя:
Выдача → Читатели → выбрать строку → Карточка выбранного читателя.
Можно открыть двойным щелчком. Карточка доступна администратору и библиотекарю.
Содержит контакты и даты, текущие книги со сроками/днями просрочки и полный
личный журнал. После возврата книгу видно только в истории; при следующем
открытии карточка заново читает данные. Для нового читателя списки пустые.

database.py: get_reader_card(reader_id) возвращает reader, loans, history.
Все три запроса читают один снимок данных через BEGIN и фильтруются параметром ?.
Текущие книги определяет copies.reader_id, история — operations.reader_id,
поэтому новая выдача того же экземпляра не переносит прошлую историю другому читателю.
История без лимита в 100 записей. Неизвестный билет → ValueError.
ui/workflows.py: ReaderCardDialog, две таблицы во вкладках QTabWidget.
ReadersPage сохраняет id билета в UserRole, поэтому сортировка не ломает выбор.

срок старой выдачи сам по себе не означает текущую просрочку.
Схема SQLite, четыре кнопки главного меню и requirements.txt не изменены.

исправление оформления macOS — 18.11.2026

Причина чёрного фона: стиль задавал тёмный текст, а таблицы, поля и строка
состояния получали тёмную системную палитру macOS.
main.py: apply_light_theme(app) включает Fusion и явную светлую QPalette
для активных и неактивных окон. Цвета фона, текста, выделения и подсказок
заданы вместе; таблицы, заголовки и строка состояния также оформлены в STYLE.
Внутренние поля счётчиков не получают лишнюю рамку QLineEdit.
Тема приложения остаётся светлой при тёмной теме macOS; настройки системы не меняются.

19 автотестов пройдены. Новая проверка начинает с тёмной палитры и проверяет
контраст обычного и выделенного текста в таблицах, списках, полях и строке
состояния. Она также прошла на платформе Cocoa с тёмной темой системы.
На Cocoa просмотрены выдача, возврат, список читателей в выпадающем меню
и администрирование. Проверки используют временные базы; рабочие БД не изменены.
